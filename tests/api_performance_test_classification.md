# API 성능 테스트 TC 분류 체계

## 📋 분류 개요

API 성능 테스트는 시스템의 응답 속도, 안정성, 확장성을 검증하기 위한 테스트입니다.
다음과 같이 7가지 주요 카테고리로 분류됩니다.

---

## 1️⃣ 부하 테스트 (Load Testing)

**목적**: 정상적인 사용자 부하 상황에서 시스템의 성능을 측정

**측정 지표**:
- 평균 응답 시간 (Average Response Time)
- 95/99 백분위수 응답 시간 (95th/99th Percentile)
- 초당 요청 처리량 (Requests Per Second, RPS)
- 에러율 (Error Rate)
- CPU/메모리 사용률

**테스트 시나리오 예시**:
- 100명 동시 사용자, 10분간 지속
- 500명 동시 사용자, 30분간 지속
- 예상 피크 타임 사용자 수의 80% 부하

---

## 2️⃣ 스트레스 테스트 (Stress Testing)

**목적**: 시스템 한계점을 찾고, 과부하 상황에서의 동작 확인

**측정 지표**:
- 시스템 한계점 (Breaking Point)
- 장애 발생 시점의 동시 사용자 수
- 장애 복구 시간 (Recovery Time)
- 에러 메시지 적절성

**테스트 시나리오 예시**:
- 점진적으로 부하 증가 (100 → 500 → 1000 → ... 사용자)
- 시스템이 실패할 때까지 부하 증가
- 한계점 도달 후 부하 감소 시 복구 여부 확인

---

## 3️⃣ 스파이크 테스트 (Spike Testing)

**목적**: 급격한 트래픽 증가 시 시스템의 대응 능력 검증

**측정 지표**:
- 급증 시점의 응답 시간 증가율
- 에러 발생 여부
- 오토스케일링 반응 시간
- 정상화까지 소요 시간

**테스트 시나리오 예시**:
- 10명 → 1000명으로 즉시 증가
- 플래시 세일, 이벤트 오픈 시나리오
- 5분 유지 후 정상 부하로 복귀

---

## 4️⃣ 내구성 테스트 (Endurance/Soak Testing)

**목적**: 장시간 지속적인 부하에서 메모리 누수, 리소스 고갈 등 확인

**측정 지표**:
- 시간 경과에 따른 응답 시간 변화
- 메모리 사용량 추이
- 데이터베이스 커넥션 풀 상태
- 디스크 I/O 사용률

**테스트 시나리오 예시**:
- 300명 동시 사용자, 4시간 지속
- 500명 동시 사용자, 8시간 지속
- 주말 야간 테스트 (24시간)

---

## 5️⃣ 확장성 테스트 (Scalability Testing)

**목적**: 사용자 증가에 따른 시스템 확장성 검증

**측정 지표**:
- 사용자 수 대비 응답 시간 증가 비율
- 수평/수직 확장 효율성
- 리소스 추가 시 성능 개선율
- 비용 대비 성능 효율

**테스트 시나리오 예시**:
- 100, 500, 1000, 2000명 단계별 테스트
- 서버 인스턴스 1개 → 2개 → 4개 확장 테스트
- DB 커넥션 풀 크기 조정 효과 측정

---

## 6️⃣ 동시성 테스트 (Concurrency Testing)

**목적**: 동시 다발적 요청 처리 능력 및 데이터 일관성 검증

**측정 지표**:
- 동시 트랜잭션 처리 성공률
- 데드락 발생 빈도
- 데이터 정합성 유지 여부
- 동시성 제어 메커니즘 동작 확인

**테스트 시나리오 예시**:
- 동일 상품에 대한 100명 동시 구매 시도
- 동일 계좌에 대한 동시 입출금 처리
- 재고 차감 로직의 race condition 테스트

---

## 7️⃣ API 엔드포인트별 응답시간 테스트

**목적**: 개별 API의 성능 SLA 준수 여부 확인

**측정 지표**:
- 평균 응답 시간 (SLA: 예: 200ms 이하)
- 최대 응답 시간
- 타임아웃 발생률
- 캐싱 효율성

**테스트 시나리오 예시**:
- GET /api/products - 상품 목록 조회 (목표: 100ms 이하)
- POST /api/orders - 주문 생성 (목표: 500ms 이하)
- GET /api/search - 검색 (목표: 200ms 이하)
- PUT /api/users/:id - 사용자 정보 수정 (목표: 300ms 이하)

## 🎯 테스트 환경 고려사항

### 네트워크 조건
- 로컬 네트워크 vs 실제 인터넷 환경
- 지역별 레이턴시 (국내, 해외)
- 3G/4G/5G/WiFi 다양한 네트워크 대역폭

### 데이터 조건
- 초기 DB 데이터 볼륨
- 캐시 warming 여부
- 테스트 데이터 분포 (신규/기존 사용자)

### 시스템 구성
- 프로덕션과 동일한 인프라 구성
- 모니터링 도구 설정 (APM, 로그 수집)
- 데이터베이스 인덱스 상태

## 📊 성능 테스트 도구 추천

- **JMeter**: 오픈소스, 다양한 프로토콜 지원
- **K6**: 개발자 친화적, JavaScript 기반
- **Gatling**: Scala 기반, 높은 성능
- **Locust**: Python 기반, 확장 용이
- **Artillery**: Node.js 기반, 간단한 설정
