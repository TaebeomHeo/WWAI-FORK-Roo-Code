## 📄 Requirement Summary  
The requirement is to design test cases that validate the login functionality of an e‑commerce platform.  
Assumptions (based on typical e‑commerce login flows):

1. **Login Page** – Contains fields for *Email/Username* and *Password*, a *Login* button, and links for *Forgot Password* and *Register*.
2. **Authentication** – Supports email/password login only (no social logins).
3. **Validation Rules**  
   - Email must be in a valid format.  
   - Password must be at least 8 characters.  
   - Both fields are mandatory.  
4. **Error Messages** – Specific messages for invalid credentials, empty fields, and incorrect format.  
5. **Security** – Password is masked; no auto‑fill.  
6. **Post‑Login** – Successful login redirects to the user’s dashboard or the last visited page.

---

## 🎯 Test Scope  
- **Positive scenarios**: Valid login, login with previously saved credentials, login after registration.  
- **Negative scenarios**: Empty fields, invalid email format, short password, incorrect credentials, password masking, login page layout.  
- **Edge cases**: Extremely long input strings, special characters, SQL injection attempt, XSS attempt.  
- **Security & usability**: Password visibility toggle, error message clarity, redirect behavior.
